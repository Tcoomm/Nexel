# Спецификация языка Nexel

## 1. Введение

Nexel — учебный императивный язык программирования с синтаксисом, близким к C. Программа располагается в одном исходном файле, точкой входа является функция `void main()`.

В третьей итерации поддерживаются целочисленные выражения, глобальные и локальные переменные, функции с параметрами и возвращаемыми значениями, арифметические операции, ввод через `readInt()` и вывод через `print()`. Инструкции завершаются точкой с запятой.

Лексический анализатор также распознаёт конструкции, предназначенные для следующих итераций.

## 2. Лексика

### 2.1. Пробельные символы

Вне строковых литералов игнорируются:

| Символ | Обозначение |
| --- | --- |
| пробел | ` ` |
| горизонтальная табуляция | `\t` |
| перевод строки | `\n` |
| возврат каретки | `\r` |

### 2.2. Комментарии

Поддерживаются два вида комментариев:

- `//` — однострочный комментарий;
- `/* ... */` — многострочный комментарий.

Вложенные многострочные комментарии не поддерживаются.

### 2.3. Идентификаторы

Идентификатор состоит из латинских букв, цифр и символа `_`. Первый символ должен быть латинской буквой или `_`.

```text
identifier ::= (letter | "_") (letter | digit | "_")*
letter     ::= "a".."z" | "A".."Z"
digit      ::= "0".."9"
```

Кириллица в идентификаторах не допускается.

### 2.4. Ключевые слова

Зарезервированные слова:

```text
int string bool void
if else while return struct
true false
```

Имена `main`, `print` и `readInt` распознаются как идентификаторы.

### 2.5. Целочисленные литералы

Целочисленный литерал — непустая последовательность десятичных цифр:

```text
integer_literal ::= digit+
```

Допустимый диапазон значений: от 0 до 2147483647. Знак `-` обрабатывается как отдельный унарный оператор.

### 2.6. Строковые литералы

Строковый литерал заключается в двойные кавычки:

```text
string_literal ::= '"' (string_char | escape)* '"'
```

Здесь `string_char` — символ, кроме неэкранированных кавычки, обратной косой черты и перевода строки; `escape` — одна из последовательностей:

| Последовательность | Назначение |
| --- | --- |
| `\"` | двойная кавычка |
| `\\` | обратная косая черта |
| `\n` | перевод строки |
| `\r` | возврат каретки |
| `\t` | горизонтальная табуляция |

### 2.7. Логические литералы

`true` и `false` являются ключевыми словами.

### 2.8. Операторы

| Категория | Операторы |
| --- | --- |
| арифметические | `+` `-` `*` `/` `%` |
| присваивание | `=` |
| сравнение | `==` `!=` `<` `<=` `>` `>=` |
| логические | `&&` `\|\|` `!` |

Одиночные `&` и `|` недопустимы.

### 2.9. Разделители

| Лексема | Назначение |
| --- | --- |
| `(` `)` | круглые скобки |
| `{` `}` | фигурные скобки |
| `[` `]` | квадратные скобки |
| `;` | конец инструкции |
| `,` | разделитель элементов |
| `.` | разделитель доступа к полям |

## 3. Синтаксис

Программа состоит из объявлений глобальных переменных и определений функций. Точка входа — единственная функция `void main()` без параметров. Функции содержат блоки инструкций; блоки могут быть вложенными.

В третьей итерации поддерживаются только переменные типа `int` и функции с результатом `int` или `void`. Объявление переменной обязательно содержит инициализатор. Присваивание является отдельной инструкцией, а не выражением.

### 3.1. EBNF-грамматика

```ebnf
program = { external_declaration } ;

external_declaration = global_variable_declaration
                     | function_definition ;

global_variable_declaration = "int", identifier, "=", global_initializer, ";" ;

global_initializer = global_additive_expression ;
global_additive_expression = global_multiplicative_expression,
    { ("+" | "-"), global_multiplicative_expression } ;
global_multiplicative_expression = global_unary_expression,
    { ("*" | "/" | "%"), global_unary_expression } ;
global_unary_expression = { "+" | "-" }, global_primary_expression ;
global_primary_expression = integer_literal
                           | "(", global_initializer, ")" ;

function_definition = function_return_type, identifier,
    "(", [ parameter_list ], ")", block ;
function_return_type = "int" | "void" ;
parameter_list = parameter, { ",", parameter } ;
parameter = "int", identifier ;

block = "{", { statement }, "}" ;

statement = local_variable_declaration
          | assignment_statement
          | return_statement
          | block
          | expression_statement ;

local_variable_declaration = "int", identifier, "=", expression, ";" ;
assignment_statement = identifier, "=", expression, ";" ;
return_statement = "return", [ expression ], ";" ;
expression_statement = expression, ";" ;

expression = additive_expression ;
additive_expression = multiplicative_expression,
    { ("+" | "-"), multiplicative_expression } ;
multiplicative_expression = unary_expression,
    { ("*" | "/" | "%"), unary_expression } ;
unary_expression = { "+" | "-" }, primary_expression ;
primary_expression = integer_literal
                   | "(", expression, ")"
                   | identifier, [ call_suffix ] ;

call = identifier, call_suffix ;
call_suffix = "(", [ argument_list ], ")" ;
argument_list = expression, { ",", expression } ;

integer_literal = digit, { digit } ;
identifier = identifier_start, { identifier_part } ;
identifier_start = letter | "_" ;
identifier_part = letter | digit | "_" ;
```

В `primary_expression` общая форма `identifier, [ call_suffix ]` означает чтение переменной, если хвоста вызова нет, и вызов функции, если присутствует `(...)`. Правило `call` именует второй вариант этой формы.

У `external_declaration` также есть общая начальная часть `int identifier`. После неё `(` означает определение функции, а `=` — объявление глобальной переменной. Это различие следует обрабатывать факторизованным разбором.

Глобальный инициализатор намеренно использует отдельную группу правил: в нём разрешены только целочисленные литералы, скобки и арифметические операции. Имена переменных и вызовы функций в нём грамматически недопустимы.

### 3.2. Приоритеты операторов

| Приоритет | Операторы | Ассоциативность |
| --- | --- | --- |
| 1 (высший) | унарные `+`, `-` | справа налево |
| 2 | `*`, `/`, `%` | слева направо |
| 3 (низший) | `+`, `-` | слева направо |

Оператор `%` вычисляет остаток от целочисленного деления.

`readInt()` считывает целое число из стандартного ввода.

`print(expression)` выводит значение выражения с переводом строки.

Результат выражения-инструкции отбрасывается.

### 3.3. Переменные и области видимости

Все переменные и параметры имеют тип `int`. Инициализация обязательна как для глобальных, так и для локальных переменных:

```c
int globalValue = 10;

void main() {
    int localValue = globalValue + 5;
    localValue = localValue * 2;
    print(localValue);
}
```

Глобальные переменные объявляются на верхнем уровне программы. Они доступны из тел функций. Все глобальные инициализаторы вычисляются до вызова `main` в порядке объявлений. Поскольку глобальный инициализатор может содержать только литералы и арифметику, он не может читать другую переменную, вызывать функцию или выполнять ввод-вывод.

Локальная переменная видна начиная с места объявления и до конца блока, в котором объявлена. При разборе и проверке инициализатора имя новой переменной ещё не добавлено в текущее окружение. Поэтому `int x = x + 1;` допустимо только тогда, когда до объявления доступна другая переменная `x` во внешней области.

В пределах одного блока повторное объявление имени запрещено. Вложенный блок образует новую область видимости и может объявить переменную с именем внешней переменной. Такое затенение не изменяет значение внешней переменной:

```c
void main() {
    int value = 1;
    {
        int value = 2;
        print(value); // 2
    }
    print(value); // 1
}
```

Параметры функции и её внешний блок тела образуют одну область видимости. Поэтому параметр нельзя повторно объявить локальной переменной непосредственно во внешнем блоке функции. Во вложенном блоке затенение параметра разрешено.

Области видимости лексические, а не динамические: функция видит глобальные переменные и собственные локальные переменные/параметры, но не получает доступ к локальным переменным функции, которая её вызвала.

Имена глобальных переменных не могут совпадать с именами функций. Имена `main`, пользовательских функций и встроенных функций нельзя использовать для локальных переменных и параметров. Повторные объявления переменных в одной области видимости запрещены.

Присваивание записывается отдельной инструкцией `identifier = expression;`. Цепочки присваиваний (`a = b = 1`) и присваивания внутри выражений не поддерживаются.

### 3.4. Функции и вычисления

Функции объявляются только на верхнем уровне. Поддерживаются функции двух видов:

- `int` — функция обязана вернуть целочисленное значение;
- `void` — функция не возвращает значение.

Параметры имеют тип `int`. Функции могут иметь любое количество параметров, в том числе ноль. Перегрузка и вложенные определения функций не поддерживаются.

В программе должна быть ровно одна точка входа `void main()` без параметров. Явный вызов `main()` из исходной программы запрещён. Пользовательскую функцию можно вызвать до её определения: при проверке программы сначала собираются сигнатуры всех функций, затем проверяются их тела.

Аргументы вызова вычисляются слева направо. Параметры получают значения по значению: изменение параметра внутри функции не изменяет переменную вызывающего кода. Операнды арифметических выражений также вычисляются слева направо.

Правила возврата:

- `return expression;` используется в функции `int`; выражение должно иметь тип `int`.
- `return;` используется в функции `void`.
- Функция `void`, достигшая конца тела, завершается неявным возвратом.
- Функция `int` должна гарантированно вернуть значение.
- `return` внутри вложенного блока завершает всю текущую функцию, а не только блок.

Вызов функции `void` разрешён только как самостоятельная инструкция. Его нельзя использовать как значение в арифметике, аргументе другой функции, инициализаторе переменной или `return expression`. Результат выражения-инструкции типа `int` отбрасывается; после вызова `void` удалять значение со стека не требуется.

Синтаксические и семантические ошибки должны обнаруживаться до запуска виртуальной машины. Если в программе есть ошибка компиляции, никакие инструкции программы не выполняются: в частности, предшествующий ошибке `print` не должен успеть вывести данные.

### 3.5. Встроенные функции и ограничения

Встроенные функции доступны без отдельного объявления. Для каждой функции требуется точное число аргументов:

| Функция | Аргументы | Результат | Поведение |
| --- | --- | --- | --- |
| `readInt()` | 0 | `int` | Считывает одну строку стандартного ввода и разбирает знаковое десятичное 32-битное целое число. |
| `print(value)` | 1 (`int`) | `void` | Выводит значение с переводом строки. |
| `abs(value)` | 1 (`int`) | `int` | Возвращает модуль числа. Для минимального `int` возникает ошибка переполнения. |
| `min(left, right)` | 2 (`int`) | `int` | Возвращает меньшее из двух значений. |
| `max(left, right)` | 2 (`int`) | `int` | Возвращает большее из двух значений. |

`readInt`, `print`, `abs`, `min` и `max` являются именами встроенных функций. Их нельзя повторно объявлять как пользовательские функции или использовать в качестве имён локальных переменных и параметров. Встроенные функции не поддерживают произвольное число аргументов.

Числовые литералы сохраняют диапазон второй итерации: от `0` до `2147483647`. Знак `-` является отдельным унарным оператором. Поэтому литерал `-2147483648` напрямую не записывается; минимальное значение `int` можно получить вводом или выражением `-2147483647 - 1`. Переполнение арифметики и деление на ноль являются ошибками выполнения.

В грамматику третьей итерации не входят `if`, `else`, циклы, массивы, структуры, строковые и логические выражения, операции сравнения и логические операции. Лексический анализатор может распознавать некоторые соответствующие зарезервированные слова и символы для будущих итераций, но это не означает, что такие конструкции разрешены синтаксисом Nexel этой итерации.
